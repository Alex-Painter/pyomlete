# Add a recipe (AI recipe creation)

`/create`, headed `Add a recipe`, turns one input into a saved recipe. The single field takes a link (imported: schema.org scrape, Haiku structures the ingredients, Opus as a fallback) or a description of a dish or what's in the fridge (generated by Claude Opus). `Take photo` and `Choose photos` add photos of a recipe instead (extracted by Claude). It ends on the saved recipe with `Add to list` and `Open`. New ingredients are embedded with Voyage and canonicalised through `$vectorSearch`.

## Sub-features

- `create-import-url` imports from a link (`POST /api/recipes/import-from-url/`). The button reads `Import recipe` once the field looks like a URL. The same URL is not imported twice: a 409 shows `You've already saved that one. Open it`.
- `create-generate` generates from a description (`POST /api/recipes/generate/`); the button reads `Create recipe`.
- `create-extract` reads photos (`POST /api/recipes/extract-from-images/`); the button reads `Read N photos`, and several photos are one recipe.
- `create-result` shows `Saved to your recipes` with `Add to list` and `Open`.

## How to get to it (user POV)

- The `Add` tab (phone) or the `Add recipe` button (desktop nav) goes to `/create`.
- The field is labelled `Recipe link or description`.

## Driving it with omlete-verify browse

Preconditions:

- **Real `ANTHROPIC_API_KEY` and `VOYAGE_API_KEY`** in `server/.env` or the environment before `$V up`. See "Using real keys" in `../SKILL.md`; keep the default `local` DB mode.
- Without them, report this feature as `verified-unreachable: no ANTHROPIC_API_KEY/VOYAGE_API_KEY`.
- Import also needs outbound internet to the recipe site.

- **Page renders.** This works without keys. Run `$V browse /create --expect "Add a recipe" --expect "Take photo"`.
- **Generate.** Run `$V browse /create --label create-generate --fill "Recipe link or description=eggs, spinach, feta" --timeout 120000 --click-button "Create recipe" --expect "Saved to your recipes"`. Then `curl -s http://127.0.0.1:8000/api/recipes/` shows a new non-fixture recipe at the top.
- **Without keys (expected failure).** The same command FAILs and the page shows `Something went wrong making that recipe. Try again.`; `.verify-run/api.log` shows `anthropic.AuthenticationError`. Useful as a negative control.

## Gotchas

- With the placeholder keys the API still boots, but these endpoints return 500 with `anthropic.AuthenticationError` in `.verify-run/api.log`.
- The local atlas-local DB starts with no Atlas Search / vector index, and nothing in the repo creates one. How `find_similar_ingredients` behaves there is not yet verified. Record it here after the first keyed run.
- Each successful run spends real API tokens and writes new `ingredients` documents. Run against the local DB only.
- Adding photos disables the text field; remove the photos to type again.
